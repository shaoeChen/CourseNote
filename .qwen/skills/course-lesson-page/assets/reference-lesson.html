01

把模型做大：Scaling Law

▶ 00:02:31
一句話重點

只要增加算力、資料量與參數量，模型的 test loss 就會以可預測的方式下降；這條「可預測的進步曲線」是 GPT-3 以來 LLM 發展的引擎。

BERT、T5 這些早期語言模型本來就不錯，但 GPT-3 之後大家發現一件驚人的事：光是把參數量放大，模型就會明顯變好。這個規律被整理成 scaling law，成為訓練 pre-training 基礎模型的指導原則。它有三條可以各自放大的軸：

以上為示意圖：橫軸是各自的規模，縱軸是 test loss，曲線形狀僅表達「越大越低」的趨勢。

模型規模的指數成長

各模型的參數量，單位為 B（十億）。橫軸為 log 刻度，每一格代表 10 倍。

資料來源：課堂投影片與講者口述。GPT-4 的參數量並未公開，空心圓為講者提到的估計值（達兆級，即 1,000B 以上）。

為什麼要在意模型變大？

效果一

Benchmark 全面進步

自然語言、多語言與推理類的 benchmark 成績隨規模持續上升。

效果二

學會 few-shot learning

過去得為每個領域 fine-tune；現在給幾個範例就能照著做，原型開發變得非常容易。

效果三

出現 emergent behavior

像推理這類能力，只會在夠大的模型中浮現，而且事前無法預測。

伏筆：這條「越大越好」的路線長期是各種做法的基礎，但講者指出它從 2024 年左右開始碰到某種 saturation point，這正是後面 test-time scaling 登場的背景。

大模型不需要針對任務重新訓練：只靠 prompt 裡的任務描述（zero-shot），或再加上幾個範例（few-shot），就能完成沒被專門訓練過的任務。

03

Chain of Thought：最重要的 Emergent Behavior

▶ 00:07:15
一句話重點

範例裡不只給答案，還示範「怎麼想」，模型就會把這套推理流程套到新問題上；但這個效果只有在模型夠大時才會出現。

Scaling law 讓我們能預測 loss 會怎麼下降，卻預測不了模型變大後會冒出哪些新能力。這些「做出更大的模型、親眼看到之前無從得知」的能力稱為 emergent behavior，其中最重要的一個就是 chain of thought（簡稱 CoT）。

Standard prompting

範例只有題目與答案

範例
問：Roger 有 5 顆網球，他又買了 2 罐，每罐 3 顆。現在共有幾顆？
答：11 顆。
新問題
問：餐廳原有 23 顆蘋果，用掉 20 顆做午餐，又買了 6 顆。現在有幾顆？
答：27 顆。答錯

Chain-of-thought prompting

範例多了推理過程

範例
問：Roger 有 5 顆網球，他又買了 2 罐，每罐 3 顆。現在共有幾顆？
答：原本有 5 顆。2 罐各 3 顆是 6 顆。5 + 6 = 11。答案是 11 顆。
新問題
問：餐廳原有 23 顆蘋果，用掉 20 顆做午餐，又買了 6 顆。現在有幾顆？
答：原有 23 顆，用掉 20 顆剩 3 顆。再買 6 顆，3 + 6 = 9。答案是 9 顆。答對

Roger 的例子是講者在課堂上使用的；蘋果題取自同一篇論文（Wei et al., 2022）的圖示，用來示範「把流程套到新問題」。

CoT 的效果隨模型規模浮現

GSM8K（國中程度數學應用題）的解題率，橫軸為參數量（B＝十億）。把滑鼠移到資料點上可看數值。

Standard prompting Chain-of-thought prompting 先前 supervised 方法的最佳成績
以表格檢視數據

數值取自 Wei et al.,〈Chain-of-Thought Prompting Elicits Reasoning in Large Language Models〉（2022），為依論文圖表整理的近似值。

圖表要讀的重點有兩個。第一，小模型幾乎無法從 CoT 受益，兩條線貼在一起；第二，模型一大，兩條線就拉開，PaLM 在 540B 時甚至追上先前專門訓練的 supervised 方法。同樣的現象也出現在其他任務上，例如 modular arithmetic、word unscramble，都是到了某個規模才「突然會了」。

到今天還成立嗎？Roger 這種題目，現在連 1B 參數的模型不靠範例也能解。但「先產生推理過程，答案就會更好」這個性質依然成立，而且正是 reasoning model 的核心。這也是 frontier lab 仍想持續推進 scaling 的原因之一：規模往上走，才會看到更多 emergent behavior。
04

從 GPT-3 到 ChatGPT：訓練管線

▶ 00:10:51
一句話重點

ChatGPT 的躍進不只來自更大的模型，而是在 pre-training 之後多做了三件事：用高品質資料 fine-tuning、instruction tuning，以及 RLHF。

ChatGPT 在 2022 年 11 月推出，只花 5 天就達到 100 萬用戶，是史上最成功的軟體之一。剛完成 pre-training 的模型雖然「統計上大致知道世界的樣貌」，卻沒有對錯的概念，也不知道怎麼遵循指令。後續每個階段都在補上這塊。點選各階段查看細節：

Alignment 仍是未解的大問題。引導模型符合人類的目標、偏好與價值觀，目前還沒有被真正掌握。常見做法是拿 base model，用與 sensibleness、safety 相關的精選資料 fine-tune，讓它知道什麼安全、什麼合理。

直到 2024 年初，pre-training 加 fine-tuning 一直是進步的主戰場。此後，推論階段（inference）成為新的前沿。

05

Test-time Scaling：推論時多花算力

▶ 00:19:39
一句話重點

模型參數完全不動，只是同一題問很多次、再用 verifier 挑出對的那個，小模型的解題能力就能超過大模型的單次作答。

Azalia 的實驗室在 2024 年發表了〈Large Language Monkeys〉，名字來自「無限猴子定理」：讓一隻猴子永遠在打字機上亂敲，總有一天會敲出莎士比亞的作品。這裡把 LLM 當成那隻猴子，做法只有兩步：

第一步

Repeated sampling

同一個問題平行地問很多次。模型的輸出本來就有變異，可用 temperature 調整變異程度，因此每次會得到不同的候選答案。

第二步

Verifier 挑選

用 verifier 或某種選擇機制找出正確的候選。寫程式的任務中，verifier 可以就是 unit test：哪一版通過全部測試就選哪一版。

動手試試：取樣數與 coverage

這是一個示意模擬，數字並非真實實驗結果。假設有 100 道題，小模型每次作答的成功率依題目難度而不同。拖動滑桿改變每題的取樣數 k。

每題取樣數 k1
小模型的 coverage（至少一個樣本答對）0%
對照：較強模型單次作答35%
小模型的 coverage 較強模型單次作答
每題取樣數 k（log 刻度）
已有至少一個樣本答對的題目 尚未解出的題目

實際的實驗結果

論文在 MiniF2F-MATH（形式化證明）、CodeContests、MATH 與 GSM8K 四個 benchmark 上，把每題的取樣數從 1 一路拉到 10,000。只取一個樣本時，Llama-3-8B 與 Llama-3-70B 都輸給 GPT-4o；但取樣數夠多之後，它們的 coverage 在這些 benchmark 上都超過 GPT-4o 的單次作答。而且 coverage 與取樣數之間呈現近似 log-linear 的關係，等於在推論階段也看到了一條 scaling law。

這代表什麼

模型知道的比單次輸出更多

只問一次所看到的，遠低於模型實際具備的能力。有些難題在 10,000 個樣本裡只有三、四個是對的，必須把推論規模放得夠大，才碰得到模型真正的能力上限。

為什麼叫 test-time

完全沒有動到參數

模型是固定的，改變的只有「使用模型那一刻」的生成策略。Repeated sampling 只是其中一種做法，還有許多其他形式。

把迴圈接起來：Test-time 產生的資料回頭訓練模型

DeepSeek-R1、OpenAI 的 o1 系列與 Gemini 的 thinking model 屬於同一波發展，核心創新是把 test-time scaling 與 fine-tuning 接在一起：

Pre-training
→
Fine-tuning
→
Test-time
Test-time 產生的高品質 reasoning trace 成為 synthetic data，回頭用來 fine-tune 模型

有了 test-time scaling，模型就像多了一具引擎，可以大量產生 synthetic data。例如已知答案的數學題，可以讓模型產生各種解法、留下最後收斂到正確答案的那些；程式題則留下通過測試的解。這些資料再拿來訓練，模型變好之後又能產生更好的資料。這個沒有明確上限的自我改進迴圈，正是這門課的主題。

06

Reasoning Model：學會思考的模型

▶ 00:30:18
一句話重點

Reasoning model 在回答前會自己產生一段 chain of thought；思考時間（test-time compute）花得越多，一次就答對的機率（pass@1）越高。

動機很直觀：遇到難題時，人會想久一點、嘗試不同策略。OpenAI 在 2024 年 9 月發表 o1 時，展示了困難數學 benchmark 上 pass@1 準確率與 test-time compute 之間的 log-linear 關係。過去這種 scaling 關係只在訓練階段看得到，現在參數量不變，也能在推論階段看到。

做法在推論階段多花的算力用在哪主要提升的指標
Repeated sampling平行產生很多個獨立答案coverage／pass@k：k 個裡至少一個對
Reasoning model單一答案之前先產生更長的思考過程pass@1：一次就答對

兩者的差別可以這樣理解：base model 本來就能產生各式各樣的推理鏈，只是不知道哪一條正確；訓練的目的，就是讓模型自己學會哪個答案是對的，於是 coverage 的潛力被轉換成 pass@1 的實力。

Reasoning model 學會的五種能力

以講者舉的 o1 範例說明：使用者要求寫一個 bash script，讀入一個矩陣並輸出它的 transpose。右側的思考內容為依課堂描述改寫的示意。

這些能力有一部分來自人類整理進訓練資料的示範，但很大一部分是模型在 fine-tuning 與 RL（例如以 synthetic data 進行的 RL）過程中自己學到的，而且能泛化到沒見過的問題。和一般 CoT 最大的不同在於：這條思考鏈是模型自己產生的，不是使用者寫在 prompt 裡的。

擅長

推理型任務

數學計算、資料分析、程式設計等，o1 這類模型推出時通常都勝過 GPT-4o。

不一定佔優勢

偏主觀的文字工作

個人化寫作、文字編輯這類任務，reasoning model 不見得比較好。

07

從 LLM 到 Agent

▶ 00:40:58
一句話重點

Chatbot 回答問題，Agent 完成任務：拿到一個目標後自己規劃步驟、與外部環境互動、根據回饋修正，並決定何時停止。

不論是 chatbot 還是 reasoning model，互動方式基本上仍是「一問一答」。它們很有趣，卻不一定能真的替你把事情做完。近期的轉變是 Claude Code、Codex、Deep Research 這類產品已經能端到端完成交辦的工作。

LLM

產出的是文字。事情有沒有做完、做得對不對，由使用者自己判斷並接手。

Agent 目標導向的迴圈

目標
→

→
行動
→

最後回報完成，或回報「我無法完成」。過程中需要呼叫外部工具（tool call），也需要某種 memory 來記得自己正在做什麼。

現實中多數系統是 Agentic Workflow

完全開放的 Agent 迴圈目前只在較單純的情境中可靠，例如 Deep Research 與寫程式。大多數真實場景採用的是 agentic workflow：LLM 與工具透過預先寫好的程式碼來編排。設計者先設想人類會怎麼做這件事，再把流程畫成一張固定的圖。這些 workflow 由 LLM call、verifier、critic／judge、tool call 與搜尋組成，常見的組件有六種：

08

Coding Agent 與 Verifier

▶ 00:48:14
一句話重點

寫程式之所以成為 Agent 最先成熟的領域，是因為它有現成的 verifier：測試會告訴你對不對。能取得可靠回饋的地方，自我改進的迴圈才轉得起來。

Coding agent 的工作流程

使用者透過 terminal 以自然語言下指令，Agent 與電腦環境互動。

  1. 釐清使用者意圖重複直到任務清楚使用者常常沒把需求講清楚。先問清楚，模型才知道該找什麼，以及最後要怎麼驗證。
  2. 搜尋相關檔案瀏覽 repository、搜尋檔案、查看內容，這些都是 tool call。
  3. 寫程式 → 跑測試 → 看結果重複直到測試通過在 terminal 執行指令，再依輸出決定下一步，例如「我得去改另一個檔案」。測試甚至可以由模型自己產生。
  4. 呈現完成的結果回到使用者手上；關鍵問題是：你怎麼知道它真的完成了你要的事？

講者表示，這套流程在 2024 年還不太可靠，近期才穩定下來。整體架構其實沒變，差別在於模型更強，而且用 verifiable reward 做的 RL 確實有效。模型一旦夠好，就能自己產生任務與測試，自我改進的迴圈於是啟動。

核心概念

Generator–verifier gap

模型很容易產生一大堆內容，其中有的正確、有的只是看似合理。產生答案容易，判斷答案對不對困難，兩者之間的落差就是這個 gap。只要有好的 verifier，就能把正確的那些挑出來。

目前的瓶頸

穩健的驗證很難

數學、程式這類偏規則的領域容易驗證，回饋可以直接傳回給模型。創意寫作這類領域能取得的回饋有限，人類回饋就成了瓶頸。

沒有現成 verifier 時怎麼辦？有一系列研究在處理這件事：訓練 LLM 當評審（LLM as a judge）、訓練 reward model，或讓模型搭配工具來擔任 verifier。課程後面有一整堂課專門談 verifier。

Agent 正在落地的四個場景

▶ 00:53:49
一句話重點

重複性高、流程明確、結果可驗證的工作最先被 Agent 接手；越開放的任務，目前越偏向「協助人類發想」的角色。

場景一

軟體與資料工程

  • Code migration、版本升級、重構 codebase
  • 資料抽取、清理，以及 data warehouse 遷移
  • 撰寫 unit test
場景二

客戶服務

  • 即時轉錄，留下完整紀錄
  • Knowledge assist：客服不必什麼都記得，直接查詢知識庫
  • Smart reply 與通話摘要
場景三

研究報告撰寫

給定一個複雜主題，Agent 會先判斷要看哪些參考資料、建立大綱、檢查資料是否相關、逐篇摘要，最後組成完整文章。課程作業會實際做這件事。

場景四

AI scientist

協助發想點子、迭代實驗，甚至改進論文寫作。即使模型會產生 hallucination，光是能提出大量跳脫框架的想法，就是很好的腦力激盪來源。

客服是個好例子，說明實務上的做法：把大問題拆成幾個區塊，各自用 LLM 處理效果就很好，而端到端由 Agent 完成的做法才剛開始出現。

課堂問答精選

學生在課堂上提出的問題，往往正好打在觀念最容易混淆的地方。先自己想一下答案，再展開對照。

Repeated sampling 和「窮舉所有可能答案再挑一個」有什麼不同？

候選答案仍然必須由模型產生出來。「所有可能答案」的空間遠比想像中大，不論用 tree search 還是 random search，都不可能真的走遍。模型的取樣等於是在這個空間裡挑出比較可能正確的區域。即使如此，10,000 個樣本以樣本效率來說也不算多，尤其是 MiniF2F 這種難度接近 IMO 的題目。

一次產生這麼多樣本，延遲不會很嚴重嗎？

樣本可以平行產生，所以延遲的問題相對小；真正的取捨在運算成本，而且會隨問題類型與複雜度改變。

Temperature 可以調多高來增加答案的多樣性？

不能太高，否則模型會開始胡言亂語。講者提到的經驗值是超過 1.2 通常就不太好。除了 temperature，還有其他技巧能讓回答更多樣。

取樣數可以依照題目難度自動調整嗎？

講者表示還沒看到已發表的研究這樣做，但這是值得探索的方向：如果 reward model 對題目的複雜度有概念，就能在問題尚未解決時引導系統多取樣，或決定該採用重複還是平行的嘗試方式。

Reasoning model 變強，是因為它把推理過程「寫出來」，還是訓練資料讓它本身更會想？

兩者都有。訓練資料讓模型逐漸成為通用的思考者：拆解問題、backtracking、分析，這些能力學會後能泛化到其他任務。另一方面，產生出來的思考內容每次都實際在幫它解決眼前的新問題，所以即使成本高，仍然值得讓它產生。

推理過程和最終答案，會交給不同的模型嗎？

推理能力通常隨模型規模提升，所以如果要分工，會是大模型產生 reasoning trace、小模型負責摘要答案。不過有個有趣的現象：目前的模型明顯偏好自己產生的 trace，即使別的 trace 來自更強的模型也一樣。

推理與 chain of thought 是刻意設計出來的，還是意外發現的？

Chain of thought 一開始是被「發現」的 emergent behavior：研究者注意到，只要把推理過程示範給模型看，它在難題上的表現就會變好，GSM8K 是最早出現這個跡象的資料集之一。模型讀過大量有條理的網路文字，因此本來就見過這類內容。但現在的 reasoning model 則是被刻意訓練成會推理的，它們還學會判斷什麼時候需要大量推理、什麼時候不用。至於 self-correction、backtracking 算不算 emergent，其實很難說，也可以解釋成模型見過這種行為，而 fine-tuning 又加以強化。

真正讓模型變好的是 RL，還是 pre-training 資料的多樣性？

研究圈目前沒有共識，兩種做法都有幫助。一種看法是：如果 pre-training 的作用是讓模型「大量取樣後至少有一次能答對」，那麼回饋與 RL 的作用就是把這個潛力轉成一次就答對的能力。整個迴圈還沒有被完全理解，但至少有跡象顯示持續做 RL 會讓模型持續改善。這是一個仍有大量研究空間的領域。

一頁總結

  1. 訓練階段的 scaling：算力、資料量、參數量三軸放大，loss 可預測地下降，並帶來 few-shot learning 與 chain of thought 等 emergent behavior。
  2. 讓模型好用：Pre-training 之後接上高品質資料 fine-tuning、instruction tuning 與 RLHF，模型才學會遵循指令並貼近人類偏好。
  3. 推論階段的 scaling：不改參數，靠 repeated sampling 提高 coverage，或靠 reasoning model 的長思考提高 pass@1。
  4. 自我改進的迴圈：Test-time 產生的高品質資料回頭訓練模型，模型變好後又產生更好的資料。
  5. 從回答到完成任務：Agent 需要 planning、multi-step reasoning 與 self-improvement；現階段多以預先編排的 agentic workflow 實現。
  6. Verifier 是關鍵也是瓶頸：有可靠回饋的領域（數學、程式）進展最快；如何在其他領域建立穩健的驗證，是這門課反覆出現的問題。
