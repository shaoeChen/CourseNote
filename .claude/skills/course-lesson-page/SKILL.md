# 課程教學網頁製作

把一堂課的字幕筆記變成一份讓人「學得會」的網頁。產出物是 `workdir/<課程名稱>/lesson.html`，與 `article.md` 放在同一個資料夾。

核心觀念：**這是教材，不是逐字稿的排版**。`article.md` 是依時間切段的字幕摘要，充滿重複、口語與半句話；直接美化它，讀者得到的只是比較好看的逐字稿。你的工作是先讀懂這堂課在教什麼，再重新設計一條學習路徑。

## 固定需求

這些是使用者已經定案的要求，不需要再問：

- **單一靜態檔案**：樣式與程式全部內嵌，雙擊就能開，不需要任何 backend 或建置步驟。不載入任何外部資源（CDN、網路字型、遠端圖片），因為使用者會離線開啟。唯一允許的外部連結是「跳到原始影片」的超連結。
- **全繁體中文**：內文、按鈕、圖表標籤、提示訊息都用繁體中文。只有專業術語（如 scaling law、verifier）、人名、產品名與論文名保留英文。術語第一次出現時可以附中文說明，之後直接用英文，不要在同一頁裡中英混用同一個概念。
- **深淺色與手機寬度都要能讀**：使用者會在不同裝置上複習。

需求真的有歧義時才提問（例如找不到課程資料夾、同一課程有多個版本）；其餘用合理的預設直接做，並在最後的回報裡說明你做了哪些判斷。

## 輸入資料

課程資料夾 `workdir/<課程名稱>/` 裡會用到的檔案：

| 檔案 | 用途 |
|---|---|
| `article.md` | 主要內容來源。開頭是關鍵詞清單，之後每段有投影片檔名、時間區間與重點 |
| `frames/` | 投影片截圖，檔名對應 `article.md` 裡的「簡報：」欄位。用來校正字幕錯誤、取得圖表數值 |
| `course_metadata.json` | 課程標題與來源網址（`article.md` 開頭的「來源：」也有網址） |

## 工作流程

### 1. 讀完整份 article.md

整份讀完再動手。邊讀邊記下：這堂課的主線是什麼、有哪幾個大主題、每個主題大約從哪個時間點開始、哪些地方是學生提問。

### 2. 對照投影片校正

字幕是語音辨識加上翻譯的結果，專有名詞經常出錯（實際遇過：LaMDA 被寫成 Lambda、MiniF2F 被寫成 F2F、o3 被寫成 03、coding 被寫成 encoding、公司名被直譯成中文）。把這些錯誤原封不動放進教材，會讓讀者拿錯的名詞去查資料。

挑出 8 到 15 張關鍵投影片用 Read 工具直接看圖：有圖表的、有條列清單的、標題頁、以及字幕裡名詞看起來可疑的段落。從投影片取得正確拼寫、圖表數值、論文出處與條列項目的原文。不需要看完所有截圖。

### 3. 重組成學習路徑

依概念重組，不要依時間排列。一堂 60 到 90 分鐘的課通常整理成 6 到 10 個章節。每個章節：

- 開頭放一則「一句話重點」，讓讀者只看這一句也能帶走結論
- 內文回答「這是什麼、為什麼重要、和前後章節的關係」
- 附一個時間戳連結，指向原始影片的對應位置（YouTube 用 `&t=<秒數>s`）
- 口語中的相對時間（「去年」「一年半前」）換算成絕對年份；先從投影片或內容判斷這堂課是哪一年錄的

章節之外，固定包含這些區塊，順序如下：

1. **導覽**：標題、一段導言、講者、主線圖（3 到 5 個階段，可點擊跳轉）、學習目標
2. **各章節**
3. **課堂問答精選**：把學生提問整理成可展開的問答。學生的問題往往正好打在最容易混淆的觀念上，是很好的教材
4. **一頁總結**：5 到 7 條
5. **自我檢測**：8 題左右的選擇題，選完立即顯示正解與解說。誘答選項要是真的常見誤解，不要一眼就能排除
6. **術語表**：可搜尋，涵蓋頁面中用到的英文術語

課程行政事項（評分、繳交期限）如果字幕裡有，整理成精簡的一節並註明適用對象，不要佔太多篇幅。

### 4. 為每個核心概念選擇呈現方式

先問「這個概念用什麼方式最容易懂」，再決定要不要互動。互動是為了讓讀者動手驗證觀念，不是裝飾；一個概念用一段話就能講清楚時，就用一段話。

| 概念的性質 | 適合的呈現 |
|---|---|
| 幾種做法的對照（例如不同的 prompt 寫法） | 切換按鈕，同一個區塊顯示不同版本 |
| 依序發生的階段或流程 | 逐步檢視器，或編號時間軸 |
| 「調整某個量會發生什麼事」 | 滑桿加即時圖表的模擬器 |
| 系統或架構的組成 | 用 HTML 方塊與箭頭畫的流程圖 |
| 投影片上的數據圖表 | 重新繪製成中文標籤的圖表，附表格檢視 |
| 兩類事物的差異 | 並排的對照卡片或表格 |

一份教材通常有 4 到 7 個互動元件。不要嵌入投影片截圖：它們是英文、而且多半是教室翻拍，與全中文的要求不合；圖表請重畫。

### 5. 撰寫網頁

以 `assets/reference-lesson.html` 為起點。它是一份完成並驗證過的教材（Stanford CS329A 第 1 講），裡面的版面、樣式變數與元件都可以直接沿用。先讀它的 `<style>` 區塊與你需要的元件，再替換成新課程的內容；不要從零重寫樣式。

參考檔內各元件的位置（搜尋註解即可找到）：

| 元件 | CSS 類別 | JS 區段註解 |
|---|---|---|
| 頂端列、進度條、側邊目錄、深淺色切換 | `.topbar` `.toc` | `theme`、`toc / progress` |
| 一句話重點、補充說明、卡片 | `.key` `.note` `.card` `.mini` | 無 |
| 切換按鈕與 prompt 範例框 | `.seg` `.prompt` | `02 shots` |
| 點狀圖（log 刻度） | `.dots` | `01 model sizes` |
| 折線小倍數圖與表格檢視 | `.multiples` `details.tbl` | `03 CoT small multiples` |
| 逐步檢視器 | `.steps` `.kv` | `04 pipeline` |
| 滑桿模擬器 | `.sim-top` `.cells` | `05 simulator` |
| 流程圖 | `.flow` `.fnode` `.loopbox` `.loop3` | `07 workflow patterns` |
| 編號時間軸 | `.tl` | 無 |
| 可展開問答 | `details.qa` | 無 |
| 測驗 | `.q` `.opts` `.score` | `quiz` |
| 術語表 | `.gloss` | `glossary` |

撰寫時留意這幾件事，它們都是實際踩過的問題：

- **圖表依容器實際寬度繪製**。用 JS 讀 `clientWidth` 產生 SVG，並在視窗改變大小時重畫。用固定 `viewBox` 縮放的話，手機上的文字會小到無法閱讀。
- **圖表的顏色與文字**。資料用 `--s1`（藍）、`--s2`（橘）兩個系列色，這組配色已驗證過色盲辨識度。文字一律用墨色變數，不要用系列色。兩個以上的系列要有圖例；有數值的圖表提供表格檢視。
- **流程圖在窄螢幕要能改成直向**。橫向排列的 `.flow` 加上 `.stack` 類別，手機寬度時會自動轉成直排，否則會被裁切。
- **模擬器使用固定種子的亂數**，讓每次開啟的結果一致，文字說明才對得上畫面。
- **顏色只透過 CSS 變數指定**，深色模式才會一起切換。
- **瀏覽器儲存空間的存取包在 try/catch 裡**，從檔案系統直接開啟時可能被封鎖。

如果環境中有 `dataviz` skill，畫新類型的圖表前先載入它。

### 6. 驗證

寫完後執行檢查腳本，它會檢查內嵌程式的語法、確認沒有外部資源，並用無頭瀏覽器截圖：

```bash
python .claude/skills/course-lesson-page/scripts/check_page.py "workdir/<課程名稱>/lesson.html" "<暫存資料夾>" --anchors s1,s5,quiz
```

`--anchors` 填入含有互動元件或圖表的章節 id，腳本會為每個章節各截一張桌機與手機寬度的圖。截圖請存到暫存資料夾，不要放進專案。

腳本通過只代表沒有語法錯誤，**一定要用 Read 工具打開截圖實際看過**。檢查重點：手機寬度下有沒有內容被裁切或溢出、座標軸刻度有沒有擠在一起、圖表標籤有沒有重疊、長標題換行後是否正常。發現問題就修正並重新截圖，直到桌機與手機都正常。

腳本找不到瀏覽器時會明說；這種情況下請在回報中告知使用者版面未經目視驗證。

### 7. 回報

用繁體中文簡短回報，包含檔案位置與下列事項。這些是使用者判斷教材可信度所需要的資訊，不要省略：

- 校正了哪些字幕辨識錯誤
- 哪些圖表數值是近似值，或無法與原始來源核對
- 哪些內容不是講者原話（例如為了示範而補充的例子、示意模擬）
- 哪些字幕中的資訊因為無法確認而沒有寫入
- 驗證做到什麼程度

## 內容的誠實原則

教材會被當成正確資訊來學習與引用，所以寧可少寫，不要寫錯。

- **示意內容要標示**。模擬器、示意圖、改寫的範例，都在頁面上當場註明是示意，不代表實驗數據。
- **近似值要標示**，並註明來源（哪一篇論文、哪一張投影片）。
- **無法確認的事實不要寫**。字幕中的日期、數字、人名如果與你所知不符，又無法從投影片確認，就略過該細節，並在回報中說明。
- **講者沒說的話不要算在講者頭上**。補充的例子要註明出處。
- **頁尾註明資料來源**：這份教材整理自哪一堂課的字幕，以及校正過哪些名詞。
