# 簡報辨識模式設計

目標：修正 CS329A 類型影片中，鏡頭切換被當成換頁、段內換頁漏掉，以及代表截圖不清楚的問題。使用者已同意加入可選的混合模式；既有 algorithm 模式保留為預設。

## 流程

1. 演算法保留原 threshold、edge weight、minimum segment duration。預覽優先沿用 scenes.json；generate 依參數建立演算法時間線。
2. 每段一次請求：帶時間的字幕、段首／中間／段尾三張圖、相鄰字幕與按時間重疊配對的既有筆記；可用時附上前段可讀截圖。
3. 回傳 ok、camera_cut、multiple_slides、slide_ahead、content_mismatch 或 uncertain，以及信心、代表圖索引、證據、原因、筆記是否不符、是否需要局部分析。
4. 只有高信心的同頁鏡頭切換合併；同議題不同頁不合併。問題段最多追加一次五張圖分析，全片最多十次追加請求。局部分段須高信心、完整連續、證據有效且截圖落於對應段內才套用。局部修正可辨識比原演算法最低秒數更短的真實頁面。
5. 無法驗證或追加預算耗盡，保留原邊界並標記待確認。代表圖記錄實際解碼時間；字幕按半開區間重疊配對，切點開始的字幕歸下一段。

## 介面與資料

- `generate --scene-mode hybrid` 啟用按段審查；供應商與逾時可由 CLI 單次覆寫。移除定時掃描參數。
- `.env` 的 COURSE_NOTE_VISION_PROVIDER 指向已配置好的供應商，沿用其模型、連線與金鑰；未指定時沿用 COURSE_NOTE_PROVIDER，逾時沿用 COURSE_NOTE_LLM_TIMEOUT_SECONDS。
- `detect-slides` 需要已下載 video.mp4 與 subtitles.vtt 或 transcript.json，讀取既有筆記作為證據。預覽放在 slide_preview/，原筆記、字幕、時間線與截圖保留。呈現原因、證據、待確認範圍及請求統計。
- slide_analysis/ 保存候選切點、統計、圖片、判斷快取、分段結果與待檢查報告。
- 快取包含提示版本、原邊界、字幕、鄰段、既有筆記、模型、服務位址與圖片雜湊；不保存金鑰。成功後即保存。
- API 錯誤或不合法 JSON 停止流程並保存進度，不靜默退回 algorithm。

## 驗證與限制

測試涵蓋多圖按段審查、同頁與同議題區別、截圖先行、筆記不符、局部分段驗證、預算耗盡、證據範圍、快取失效、預覽保護及真實 OpenCV/HTTP/ffmpeg 流程。舊掃描器測試僅保留內部相容性，CLI 不再呼叫它。

沒有可讀畫面的換頁無法精確還原；取樣間出現又消失的頁面可能漏掉。VLM 品質需用實際模型檢查，合成測試與 API 測試不代表 CS329A 全片已校正。
