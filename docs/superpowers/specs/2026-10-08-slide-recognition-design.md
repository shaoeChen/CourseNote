# 簡報辨識模式設計

目標：修正 CS329A 類型影片中，鏡頭切換被當成換頁、段內換頁漏掉，以及代表截圖不清楚的問題。使用者已同意加入可選的混合模式；既有 algorithm 模式保留為預設。

## 流程

1. ContentDetector 以一秒候選間隔找畫面切換；切点及其前後各 0.5 秒加入取樣。
2. 每五秒另取樣一次，避免候選切點漏掉換頁。掃描間隔可調。
3. 用獨立設定的多圖 VLM 比較最後可讀簡報與目前畫面，回傳 same/new/unknown、可讀性、信心、品質與原因。
4. 高信心的新頁以區間細查縮小換頁範圍至 0.5 秒；無法確認時保留推估範圍，不宣告精確邊界。細查中發現的較晚新頁重新依時間序列檢查。
5. 從每個已辨識的區段選品質最高、同分較晚的可讀畫面，保存實際解碼時間供最終截圖使用。字幕依實際重疊配對，恰好在切點開始的字幕歸下一段。

## 介面與資料

- `generate --scene-mode hybrid` 啟用辨識；vision backend、掃描間隔、逾時可由 CLI 控制。
- `.env` 的 COURSE_NOTE_VISION_MODEL 必須明確指定；文字模型與視覺模型設定獨立。
- `detect-slides` 僅分析已下載 video.mp4；預覽放在 slide_preview/，原筆記與截圖保留。
- slide_analysis/ 保存候選切點、統計、圖片、判斷快取、分段結果與待檢查報告。
- 快取以提示、模型、服務位址與圖片位元組識別，不保存 API key；成功判斷後即保存。
- API 錯誤或不合法 JSON 停止流程並保存進度，不靜默退回 algorithm。

## 驗證與限制

測試涵蓋鏡頭合併、動畫、定時補查、細查、未知畫面、短頁面、快取失效、中文路徑、真實 OpenCV/HTTP/ffmpeg 流程與兩種 CLI。實際影片影格的解碼時間與 ffmpeg 截圖結果須一致。

沒有可讀畫面的換頁無法精確還原；取樣間出現又消失的頁面可能漏掉。VLM 品質需用實際模型檢查，合成測試與 API 測試不代表 CS329A 全片已校正。
