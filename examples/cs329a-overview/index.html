關於 scaling、CoT 與人類 / AI 回饋

課堂先介紹規模化與推理能力，再說明以推理示範引導模型的 chain-of-thought（CoT）。不同模型與任務的收益不同，不能把單一規模門檻當成普遍定律；推理模型也經過刻意訓練。RLHF 的偏好訊號來自人類；RLAIF 使用 AI 回饋，兩者的獎勵訊號都需要檢查品質。偏好分數並不等於客觀正確性。

更多候選消耗更多總算力。平行執行可降低部分等待時間，但不會消除成本。
把 q 拉到 0：即使候選裡常有正解，隨機選出的答案也只維持原本的單次答對率。
展開計算假設：為什麼這兩條線不同？

假設 k 個候選獨立，且每個候選的答對率固定為 p：覆蓋率 C = 1 − (1 − p)k。這是簡化的「至少一次成功」機率，不是所有真實任務的 pass@k 曲線。

這裡的 q 不是一般分類器準確率，而是：以機率 q 使用理想驗證器，只要候選有正解就選到；其餘 1−q 的情況隨機挑選。因此最終答對率 = qC + (1−q)p。演示中的正誤由模擬器預先知道；真實系統沒有這個神諭。實際輸出常有相關性與不均等題目難度，結果可能不同。

以上程式碼與工具結果為教學編寫的固定劇本，不會執行你的檔案。測試通過只代表滿足這組測試，不代表所有情況皆正確。

工具讓行動有結果

讀檔、編輯、搜尋、執行測試，都會回傳外部觀察；模型再決定下一步。

記憶讓目標不丟失

保留需求、已嘗試的方法、失敗原因與目前進度，避免每一步重新開始。

停止也要有規則

目標達成、預算耗盡或無法繼續時停止。只說「我做完了」不足以證明完成。

這個迴圈是在同一個任務內修正，不會自動更新模型權重；後續將成功軌跡用於微調 / RL，才進入訓練層面的改進。

WHEN TO USE IT

步驟已知、前後有依賴

例如讀課文 → 萃取重點 → 編寫教學 → 檢查內容。每一步有清楚責任，也能加入中間檢查。

取捨：容易控制流程，但上游錯誤可能傳到下游。

程式代理

程式碼遷移、重構、修復與測試。可执行的檢查提供較具體的回饋。

客服與研究助理

搜尋知識、即時摘要、文獻整理。要檢查來源、完整性與任務是否真正完成。

AI Scientist

提出假設、設計實驗、分析與寫作。新奇點子仍須通過科學驗證。

LLM 評審和可執行驗證，差在哪裡？

LLM 評審可以給語意與品質回饋，但可能有偏差、幻覺或共同盲點；可執行驗證器則用測試、規則或工具檢查輸出。兩者都不是萬能：不完整的測試可能漏掉問題。課堂將這個困難稱為生成器與驗證器間的落差。
